# Сущности Wikidata

Каталог сущностей [Wikidata](https://www.wikidata.org) на Compose Multiplatform.

## Предметная область

Wikidata — открытая база знаний, где каждая сущность (человек, страна, город, произведение) имеет идентификатор вида `Q42` и набор утверждений: свойство `P31` «экземпляр», `P17` «страна», `P569` «дата рождения» и т. д. Значение утверждения может быть ссылкой на другую сущность, датой, числом или строкой.

Приложение показывает:

- **список** сущностей с поиском по названию и псевдонимам;
- **карточку** сущности: описание, псевдонимы, свойства и статья в Википедии. Если значение свойства — другая сущность из каталога (`instance of`, `part of`, страна, столица…), на неё можно перейти, «назад» возвращает по одному экрану.

Интерфейс на русском и английском, светлая и тёмная тема. Данные приходят из живого Wikidata Action API. При пустом поиске загружаются актуальные версии 20 стартовых сущностей, а введённый запрос отправляется в `wbsearchentities` на английском языке. Содержимое карточек запрашивается через `wbgetentities`. Моков и сохранения данных на диск нет.

## Настройка API

Нужны JDK 21 и Android SDK (compile SDK 37, min SDK 26). Адрес API задаётся в **неотслеживаемом** `local.properties`:

```properties
wikidata.api.url=https://www.wikidata.org/w/api.php
```

Или переменной окружения `WIKIDATA_API_URL`, которая имеет приоритет. Ключ доступа публичному Wikidata API не нужен. BuildKonfig генерирует конфигурацию для всех платформ в `shared/build/`; без адреса сборка останавливается с подсказкой. Не коммитьте `local.properties`, токены или сгенерированную конфигурацию.

## Сетевой слой (ЛР4)

`HttpClient → WikidataApi → NetworkWikidataRepository → ViewModel → StateFlow → Screen`.

- Движок выбирается через `expect/actual`: OkHttp на Android (без дискового кэша), CIO на JVM, Js/Fetch на JS и wasm. Клиент имеет таймауты и закрывается при завершении App.
- DTO в `data/network` разбираются через `kotlinx.serialization` с `ignoreUnknownKeys = true`; доменные модели и UI-модели отделены от ответа API. Поддерживаются ссылки на сущности, даты, числа, строки и одноязычный текст; неизвестные виды значений и deprecated-утверждения пропускаются.
- На JVM/Android декодирование, преобразования и склейка страниц выполняются на `Dispatchers.Default`. В браузере большой ответ разбирается теми же Kotlin DTO в отдельном Kotlin/JS Web Worker (`networkWorker`), включая wasm-клиент: `Dispatchers.Default` в браузере не создаёт фоновый поток. Результат передаётся небольшими фрагментами, принимающая корутина уступает интерфейсу управление между ними. При отмене Worker завершается.
- Поиск запускается через 400 мс после ввода и отменяет предыдущую корутину. `CancellationException` пробрасывается, остальные ожидаемые ошибки переводятся в `LoadException`; ViewModel не рисует ошибку при отмене.
- Кнопка «Загрузить ещё» использует серверный `search-continue`. Дубликаты удаляются по ID. Ошибка следующей страницы сохраняет уже загруженные карточки и курсор для повтора.
- Деталь имеет состояния загрузки, содержимого, отсутствующей сущности и ошибки с повтором. Названия связанных сущностей загружаются пакетами до 50 ID, переходы доступны и за пределы стартового списка.
- Подписи ошибок локализованы. Ответы API, токены и внутренние тексты исключений пользователю не показываются.

## Запуск

Desktop:

```bash
./gradlew :desktopApp:run
```

Браузер (Wasm):

```bash
./gradlew :webApp:wasmJsBrowserDevelopmentRun
```

## Проверки

```bash
python tools/check-strings.py
./gradlew :shared:jvmTest
./gradlew :desktopApp:classes :androidApp:assembleDebug :webApp:wasmJsBrowserDistribution :webApp:jsBrowserDistribution
```

Тесты проверяют разбор неизвестных полей и типов утверждений, отсутствующую сущность, ошибки API, отмену, debounce, сохранение списка при ошибке и повтор страницы без дубликатов.

Отдельная проверка живого API (интернет обязателен):

```bash
./gradlew :shared:jvmTest "-Pwikidata.live=true" --tests "*LiveWikidataTest"
```

Android APK: `androidApp/build/outputs/apk/debug/androidApp-debug.apk`. Браузерная сборка включает `network-worker.js`; публиковать нужно всю папку `webApp/build/dist/wasmJs/productionExecutable` (или аналогичную JS-папку).

Отчёты компилятора Compose находятся в `shared/build/compose_compiler/` (включая подкаталоги таргетов). `EntityListScreen` и `EntityDetailScreen` должны быть `restartable skippable`; экраны получают только неизменяемое состояние и колбэки.
